Real-Time Customer Onboarding in BFSI

Master data consolidation and API-led integration for a mid-sized lender

Onboarding: 4 days → 11 minutes

[4] executive summary

Summary

The client's customer records lived in six systems that had never been reconciled, so every new account opening required manual verification across teams. We built a governed master data layer with API-led integration on top, giving onboarding a single trusted customer view in real time. Account opening dropped from four days to under twelve minutes, and duplicate customer records fell by 94%.

[5] challenge[] — problem → consequence

The challenge

  • No single customer record. Six source systems held overlapping customer data with no match-and-merge logic, so relationship managers could not tell whether an applicant was already a customer.
  • Manual KYC verification. Document checks were routed by email between three teams, adding two to three days to every application and leaving no audit trail.
  • Point-to-point integrations. Fourteen bespoke interfaces between core systems meant any schema change triggered weeks of regression testing.
  • No data quality enforcement. Address and identifier formats varied by channel, producing duplicate records and failed downstream regulatory reporting.
  • Reporting built on extracts. Compliance reporting relied on overnight extracts, so the picture regulators saw was always at least a day stale.

The solution

[7] approach[] — mirrors the diagram left→right

How we built it

Source connectivity and ingestion

  • Profiled six source systems and catalogued 240 customer attributes against a target model.
  • Established change-data-capture feeds from the core banking platform and the loan origination system.
  • Retired nine of the fourteen point-to-point interfaces in the first phase.

Mastering and data quality

  • Defined match-and-merge rules across name, identifier and address, tuned against a 50,000-record sample.
  • Implemented 380 data quality rules with automated remediation for the highest-volume defects.
  • Introduced survivorship rules so the golden record has a defensible, traceable lineage.

API-led integration

  • Published a customer lookup API consumed by the onboarding portal and the branch application.
  • Built system APIs over the mastered layer so consuming applications never couple to source schemas.
  • Added throttling and caching to hold sub-second response under peak branch load.

Governance and consumption

  • Stood up a business glossary and stewardship workflow with named data owners per domain.
  • Automated lineage capture end to end, replacing the manual regulatory reporting pack.
  • Handed over runbooks and trained the client's stewardship team across two cycles.
